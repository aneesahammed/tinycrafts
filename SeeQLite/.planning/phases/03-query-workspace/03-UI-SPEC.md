# Phase 3 — Query Workspace UI Design Contract

> Canonical visual and interaction contract for SQL authoring, results, query plans, cancellation/recovery, and local query history. Generated by `gsd-ui-researcher` and independently verified by the GSD UI checker.

## Sources and Precedence

1. `01-UI-SPEC.md` and the Phase 1 shell implementation are canonical for global shell, tokens, theme boot, header, explorer, focus ring, and responsive navigation.
2. This contract specializes that system for the Phase 3 workspace.
3. `03-CONTEXT.md`, `REQUIREMENTS.md` SQL-01..04, RES-01..03, PLAN-01, CANCEL-01..02, and HIST-01..02 are behaviorally binding.
4. If a local value below conflicts with a Phase 1 global token, retain the Phase 1 token and preserve the contrast, size, and behavior specified here.

## Design System

| Property | Value |
|---|---|
| Tool | Manual TinyCrafts CSS token system; no shadcn |
| Preset | Not applicable |
| Component library | None; CodeMirror 6 is the editor surface and `react-resizable-panels` is a layout primitive only |
| Icon library | Inherited small inline SVG set; icons always have text or an accessible name |
| Fonts | Self-hosted Inter for prose, headings, links, and every action; JetBrains Mono for SQL, identifiers, values, counts, timings, and metadata |
| Shape | 1px rules, 6px controls, 7px feature cards; pills only for state/badge semantics |
| Texture | Inherited restrained 36px grid on `--paper`; dense data surfaces use solid paper to protect readability |

No Tailwind, component kit, registry block, grid framework, animation library, or global state library may be introduced by this phase.

## Spacing Scale

Phase 1 owns the spacing values. This phase uses only `--space-1`, `--space-2`, `--space-4`, `--space-6`, `--space-8`, `--space-12`, and `--space-16`. Map compact control and cell-detail gaps to `--space-2`; map control padding, result metadata gaps, panel insets, and alerts to `--space-4`. There is no 12px layout spacing token.

Exceptions: 1px rules, 2px focus outline, 36px grid texture, 36px desktop result rows, 40px desktop controls/headers, and 44px coarse-pointer/mobile targets. These are component dimensions, not new spacing tokens.

## Typography

Use exactly two weights: 400 and 600. Do not use italics.

| Role | Size | Weight | Line height | Family and use |
|---|---:|---:|---:|---|
| Micro/meta | 12px | 600 | 1.35 | JetBrains Mono; uppercase section labels, shortcuts, badges, timing |
| Body/control | 14px | 400 | 1.5 | Inter; buttons/actions, alerts, help, and prose |
| Editor/data | 14px | 400 | 1.55 | JetBrains Mono; SQL, identifiers, result cells, plans, query previews, history metadata, counts, and timings |
| Section heading | 18px | 600 | 1.25 | Inter; panel and state headings only |
| Workspace title | 24px | 600 | 1.2 | Inter; inherited Query mode/page title only |

Do not shrink result text below 14px at any viewport. Long SQL and values wrap only in detail surfaces; the editor and result grid retain horizontal scrolling where semantically necessary.

## Color and Theme

Phase 1 owns every light/dark value. This phase references semantic names only:

| Usage | Required inherited tokens |
|---|---|
| Surfaces | `--paper`, `--paper-2`, `--paper-3` |
| Primary/supporting text | `--ink`, `--ink-2` |
| Decorative-only marks | `--ink-3`, `--rule` |
| Meaningful control, grid, dialog, and selected-state boundaries | `--boundary` |
| Focus | `--focus-ring` |
| Primary fill and on-fill text | `--accent`, `--on-accent` |
| Accent text and text links in both themes | `--accent-deep` |
| Selected/info surface | `--accent-soft` with `--boundary` |
| Error/destructive | `--danger`, `--danger-soft`, `--on-danger` |
| Truncation/timeout/stale state | `--warning`, `--warning-soft`, `--on-warning` |
| Completed/recovered state | `--success`, `--success-soft`, `--on-success` |

`--ink-3` and `--rule` are decorative only. All visible filenames, counts, timings, metadata, placeholders carrying instructions, disabled reasons, and status details use at least `--ink-2`. Meaningful input, button, table, selected-row, sheet, and dialog boundaries use `--boundary`. Accent-colored text uses `--accent-deep`, including in the light theme; `--accent` is reserved for the `Run query` fill, active mode/tab, selected result state, and small progress marks, while focus always uses `--focus-ring`. Status always includes icon/text and never relies on color.

Acceptance must assert 4.5:1 for normal text and 3:1 for large text, focus, meaningful control boundaries, selected states, and grid structure in both themes. Tests must explicitly cover `--ink-2` metadata, `--accent-deep` text, `--boundary` on every surface, and each semantic foreground/background/on-color combination; `--ink-3`, `--rule`, and the background grid are exempt only when truly decorative.

## Responsive Query Layout

### Desktop — 1024px and wider

- Retain the inherited app header and catalog rail. At 1440px and wider the rail starts at 280px and may resize from 240–360px; at 1024–1439px it starts at 240px.
- The main query workspace fills the remaining width and height below the header. It is a vertical split: editor pane 38% and output pane 62%, with editor minimum 220px and output minimum 260px. The persisted divider may range from 28–60%.
- Editor heading/toolbar is a 48px single row: title and database readiness left; `Build query plan`, `Run query`, or the context-specific `Stop query`/`Stop query plan` and shortcut hint right. Controls never overlay CodeMirror.
- Output begins with a 44px tab/meta row. `Results` and `Query plan` are tabs on the left; held-row count, duration, and truncation summary sit right and may wrap to a second 32px metadata line at compact desktop widths.
- History opens as a 360px right sheet over the output/editor, not as a third permanently visible column. A scrim is used only below 1440px; wide desktop keeps the underlying workspace visible but inert outside the sheet.
- The result table owns its horizontal and vertical scrolling. The document never acquires horizontal overflow.

### Tablet — 768–1023px

- Catalog becomes the inherited 320px dismissible drawer; opening it does not discard SQL or output scroll position.
- Query workspace remains a vertical split with editor 40vh (minimum 240px, maximum 52vh) and output using the remainder. The divider remains keyboard-resizable.
- Toolbar stays one row when it fits; shortcut help collapses to an accessible tooltip at widths below 880px. `Build query plan`, `Run query`, and the active context-specific stop action remain visible.
- History uses a 360px modal side sheet with scrim and focus trap. Results and Query plan remain behind it and retain state.
- Result metadata wraps below tabs; horizontal table scrolling remains inside the output surface.

### Mobile — below 768px, verified at 375px

- Use the inherited compact header and top-level mode switch. Query is one scrollable column; Catalog and History are full-height modes/drawers, never squeezed beside it.
- The query toolbar is sticky beneath the header. It contains `Build query plan` and `Run query`; while executing, the initiating action is replaced in place by `Stop query` or `Stop query plan` so the correct stop action cannot move off-screen.
- CodeMirror is at least 240px high and at most 46vh before the user scrolls. Its line gutter may narrow, but line numbers and 14px text remain.
- `Results`/`Query plan` tabs and status summary are sticky at the output start. The semantic table scrolls horizontally inside an edge-to-edge container; the page itself does not.
- History is a full-screen mode with a 52px heading row and explicit `Back to query`. Cell detail and confirmations use full-screen dialogs with 16px safe-area-aware padding.
- Touch targets are at least 44×44px. No hover is required to discover an action or truncation state.

At 200% zoom, the layout may move to the next narrower mode. No control, editor status, or output state may overlap or become unreachable.

## Editor Contract

### Structure

1. Heading: `Query` plus ready/database state.
2. Toolbar: `Build query plan`, `Run query`, or active `Stop query`/`Stop query plan`; shortcut text; persistent command status.
3. CodeMirror editor with visible label `SQL query`.
4. Inline, persistent validation/error region below the editor; never a toast-only error.

### Authoring behavior

- `Run query` submits the non-empty selection; otherwise it submits the full draft. A selection badge says `Runs selected SQL` while selection is non-empty.
- `Build query plan` uses the same selection/full-draft rule and never bypasses validation.
- Completion lists current catalog tables, views, and columns with kind text, not color-only icons. Database replacement closes completion and swaps its source before another item can be accepted.
- Do not visually parse or mark batches in JavaScript. SQLite-owned outcomes supply the messages for empty, parameterized, multiple, unsafe, and malformed statements.
- A dirty indicator is text `Unsaved draft` beside Query; it is not a persistence promise and clears only when the exact draft has been successfully placed in history or explicitly replaced.
- Editor chunk failure renders: `The SQL editor could not load.` with `Retry editor`. A plain textarea fallback is not introduced because it would silently drop required editing/accessibility behavior.

### Shortcuts

- macOS: `⌘ Enter` runs the query; `⇧ ⌘ Enter` builds the query plan.
- Windows/Linux: `Ctrl Enter` runs the query; `Ctrl Shift Enter` builds the query plan.
- `Esc` activates `Stop query` while a query runs or `Stop query plan` while a plan builds, only after an open completion menu, dialog, or sheet has consumed its own Escape behavior.
- Buttons expose matching `aria-keyshortcuts`; visible shortcut text is hidden only where space requires and remains in accessible descriptions.
- Do not override browser find, undo/redo, selection, IME composition, or screen-reader browse keys.
- When Escape stops work from the editor, recovery retains the editor caret and selection. When a stop button was activated, successful recovery moves focus to `Run query` after a query stop or `Build query plan` after a plan stop.

## Command and Recovery State Matrix

| State | Visible contract | Enabled actions | Focus/status contract |
|---|---|---|---|
| No database | `Open a SQLite database to run a query.` | `Open database` | Query controls disabled with reasons; focus stays on `Open database` |
| Editor loading | `Loading SQL editor…` | Catalog and navigation only | Polite status; no fake editor controls |
| Ready, empty | Blank editor and `Run one read-only SQLite statement.` | Edit, history, catalog; `Run query`/`Build query plan` disabled | Empty guidance linked to editor |
| Ready, draft | `Ready` | `Run query`, `Build query plan`, history | No announcement on every keystroke |
| Validation failure | Exact message below editor | Edit, context-specific retry | Alert is focused only when an action originated outside the editor; otherwise announced assertively without stealing caret |
| Running | `Running query…` and elapsed time | `Stop query`; editor remains readable/editable, both start actions disabled | Prior valid output remains marked `Previous result`; polite elapsed updates no more than once per second |
| Planning | `Building query plan…` | `Stop query plan`; both start actions disabled | Same serialized-command behavior as query execution |
| Stopping query | `Stopping query…` within 250ms | None except navigation | `Stop query` stays in place disabled; assertive one-time acknowledgement `Stopping query` |
| Stopping plan | `Stopping query plan…` within 250ms | None except navigation | `Stop query plan` stays in place disabled; assertive one-time acknowledgement `Stopping query plan` |
| Rehydrating | `Query stopped. Reopening database…` or `Query plan stopped. Reopening database…` | Edit draft; start actions disabled | Show separate rehydration elapsed time; do not imply the source file changed |
| Recovered | `Database ready again. Your SQL was kept.` | `Run query`, `Build query plan` | Announce recovery once. Retain the editor caret after Escape; otherwise focus the corresponding start action after its stop button disappears |
| Rehydrate failed | `The query stopped, but the database could not be reopened.` | `Reopen database` | Error region receives focus; no automatic retry loop |
| Timed out | `Query stopped after 30 seconds. Your SQL is unchanged.` | `Run query`, `Build query plan` | Warning status, distinct from a user stop; prior valid output remains labelled |
| Worker crash | `The database engine stopped unexpectedly.` | `Reopen database` | Error region receives focus; stack/derived diagnostics are not shown |
| Completed | `Returned {n} rows in {duration}.` plus all bounds | `Run query`, `Build query plan`, inspect result | Polite one-time announcement; focus remains on invoking control/editor |

Double activation of `Run query` or `Build query plan` while active does not queue. The disabled control description is `A database command is already running.` Late or stale results never produce visual changes or announcements.

## Results Contract

### Result header and scope

- Header states exact held rows, total columns, elapsed time, current 50-row page, and every truncation dimension: rows, columns, cells, serialized bytes, text preview, or BLOB preview.
- Required scope copy: `Showing {held} returned rows. Sorting affects these returned rows only; it does not change the query.`
- A truncated result begins with warning text, e.g. `Result stopped at 1,000 rows and 50,000 cells.` Never use an ellipsis alone as disclosure.
- Zero rows with columns: `Query completed. SQLite returned the columns below and no rows.` Zero-column successful statements are not possible under the read-only contract; if encountered, show a normalized unsupported-result error.

### Grid density

- Use a semantic `<table>` with sticky 40px header and 36px body rows; one configured page, maximum 50 rows, exists in the DOM.
- Cells use `--space-4` horizontal padding and `--space-2` vertical padding. Numbers and BigInt align right; text, NULL, and BLOB align left.
- Column width starts at 160px, minimum 96px, maximum 360px. Users may resize within these bounds; resizing never changes data or persist database-derived labels.
- Duplicate labels remain unchanged. Add a visible ordinal micro-label (`column 1`, `column 2`) and include the ordinal in the accessible header name.
- `NULL` renders as a text badge `NULL`; empty string renders as an empty-value marker `empty`; zero remains `0`; text `NULL` renders quoted only in the cell-detail type line, not altered in the grid.
- BLOB renders `BLOB · {byte count}` plus `preview` when bounded bytes exist. Truncated text renders its safe prefix and a text badge `preview limited`.
- Long cells are single-line clipped in the grid. Enter/Space on a focused cell opens Cell detail with runtime type, complete held preview, original byte length where known, truncation reason, and `Copy held value`. The dialog never fetches more data.

### Sort, page, and focus

- Header buttons cycle unsorted → ascending → descending. Only one column sorts at a time and `aria-sort` is authoritative.
- Sort compares typed held values deterministically; it does not coerce BigInt, NULL, BLOB, or mixed runtime types into misleading strings.
- After sort, focus remains on the header and a polite message announces `Sorted {held} returned rows by {label}, ascending|descending.`
- Pagination controls are `Previous page`, `Page {x} of {y}`, `Next page`. After paging, focus moves to the result caption, then the user may enter the table.
- The table has one roving focused cell. Arrow keys move one cell; Home/End move to first/last cell in the row; Ctrl/Command+Home/End move to table corners. Navigation never changes sort or page.
- At horizontal scroll boundaries provide a visible inset shadow in both themes, but do not use it as the only overflow cue; caption text says `Scroll horizontally for more columns` when overflow exists.

## Query Plan Contract

- `Results` and `Query plan` are ARIA tabs. Switching tabs never reruns SQL.
- Plan heading states `Plan for query captured at {time}` and shows a bounded two-line SQL snapshot with `View query`.
- Render `EXPLAIN QUERY PLAN` as a nested semantic list with row ID, parent relationship, and unmodified bounded detail text. Connecting rules are decorative only.
- Orphan parent IDs appear under `Unresolved plan steps` with the ID; do not discard them.
- Persistent helper copy: `SQLite describes its access strategy here; this is not a runtime cost estimate.`
- When SQL or database generation changes, clear the plan and announce `Plan cleared because the query or database changed.` A late plan cannot restore it.
- An unsupported or invalid `Build query plan` action leaves the current Results intact and shows the error beside the Query plan tab.

## History Contract

### Sheet/list

- Trigger label: `Query history` with count, never filename. Desktop/tablet use the sheet described above; mobile uses a full-screen mode. Its dismiss action is `Close query history`.
- Header contains `Query history`, `Stored in this browser`, count, and `Clear all`. No search/filter is added for the 100-entry v1 cap.
- Entries are newest first, 72px minimum height, and show status text/icon, bounded two-line SQL, local timestamp, and duration. Optional database affinity is an opaque `Same database`/`Different database` indicator only; no raw filename/path.
- Entry actions: `Open in editor` and icon/text menu `Delete entry`. Reopening a dirty editor uses the same confirmation contract as generated join SQL.
- Empty copy: `No query history yet.` / `Run a query to keep its SQL and status in this browser. Results and database files are never saved.`
- Session fallback notice: `Saved history is unavailable. New history will last for this tab only.` It is persistent but non-blocking.
- Corrupt storage notice: `Saved history could not be read and was reset. Session history is still available.`

### Destructive confirmations

- Clear dialog title: `Clear query history?`
- Body: `This removes up to 100 saved SQL entries from this browser. It does not change your database.`
- Default button: `Keep history`; destructive button: `Clear history`.
- Delete-one is immediate only if focus remains on the list and an undo control is available for the current session for 8 seconds; otherwise use `Delete this history entry?`. Clear-all has no undo and always confirms.
- After deletion, focus moves to the next entry, previous entry, or empty-state heading in that order. After Clear all, focus moves to the empty-state heading.

## Focus, Status, and Dialog Contract

- Landmark order: app header → catalog/navigation → query editor → output → history sheet/dialog. Provide skip links to Query and Output on desktop; mobile mode heading serves as destination.
- Every visible focus indicator is a 2px `--focus-ring` outline with 4px offset. Where overflow clipping would cut it off, use the Phase 1 equivalent: a non-layout-shifting pseudo-element inset 4px with a 2px `--focus-ring` border.
- Toasts may acknowledge copy only. Validation, query status, truncation, timeout, recovery, history fallback, and errors are persistent inline regions.
- One `aria-live="polite"` command region announces start/completion/recovery. Hard validation and unrecoverable failure use `role="alert"`; never duplicate the same sentence in both.
- Dialogs trap focus, close on Escape unless an operation is irreversible/in progress, restore focus to their trigger, and put initial focus on the non-destructive action.
- Responsive mode changes retain editor caret/selection, result page/sort/scroll, active output tab, history position, and focused stable item where it still exists.

## Motion

- Panel/sheet transitions: 150ms ease-out; selected-state color transitions: 120ms. No result-row entrance, loading shimmer, animated elapsed digits, or editor motion.
- Under `prefers-reduced-motion: reduce`, sheets appear without translation, scrolling is not smooth, and status changes are immediate. A static progress glyph plus text replaces spinners.
- Stop acknowledgement must never wait for an animation.

## Objective Acceptance Checks

### Visual and responsive

- [ ] At 375, 768, 1024, 1280, and 1600px, Query, Query plan, Results, and Query history have no page-level horizontal overflow; only CodeMirror/result internals scroll where required.
- [ ] Light and dark screenshots cover empty, running, truncated result, timeout, recovery, error, plan, and history-sheet states.
- [ ] The grid renders one 50-row page maximum, 40px headers, 36px rows, stable sticky headers, and duplicate-label ordinals.
- [ ] At 200% zoom every action and status remains reachable; mobile/coarse-pointer targets are at least 44×44px.

### Interaction and accessibility

- [ ] Keyboard-only users can edit, complete, Run query, Build query plan, Stop query, Stop query plan, page, sort, inspect a cell, reopen/delete/clear history, and recover without pointer use.
- [ ] `Cmd/Ctrl+Enter`, `Shift+Cmd/Ctrl+Enter`, and contextual Escape invoke the labelled query/plan/stop actions exactly as specified without breaking IME, browser, CodeMirror, dialog, or completion behavior.
- [ ] Focus/announcements match the state matrix for success, validation, timeout, each stop action, rehydrate success/failure, sort, page, and responsive-mode change.
- [ ] Axe reports no serious/critical violations in both themes at all four representative width classes.
- [ ] Rendered text contrast is at least 4.5:1 and meaningful non-text boundaries/focus are at least 3:1 in both themes; every semantic color also has text/icon meaning.

### Product truth and failure modes

- [ ] Selection/full-draft scope is visible before Run query/Build query plan; multi-statement, parameter, empty, unsafe, syntax, limit, and not-ready outcomes use actionable persistent copy.
- [ ] Every result bound is surfaced beside the result; client sort explicitly states held-result scope.
- [ ] Run query/Build query plan actions serialize; double activation cannot queue or visually replace the current command.
- [ ] `Stop query` and `Stop query plan` acknowledge the correct work within 250ms, rehydration is separately named/timed, Escape/button focus recovers as specified, the draft survives, stale output does not publish, and failure exposes one `Reopen database` action.
- [ ] History empty/corrupt/disabled/quota/full/101st-entry/clear states are visible and never block query work or imply results/database bytes were saved.
- [ ] Reduced-motion mode removes translations, smooth scrolling, shimmer, and non-essential animation without removing status feedback.

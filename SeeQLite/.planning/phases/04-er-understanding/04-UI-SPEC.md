# Phase 4 — ER Understanding UI Design Contract

> Canonical visual and interaction contract for declared-foreign-key graphing, the equivalent structured relationship path, bounded layouts, and join-SQL handoff. Generated by `gsd-ui-researcher` and independently verified by the GSD UI checker.

## Sources and Precedence

1. `01-UI-SPEC.md` and the Phase 1 implementation remain canonical for the shell, global tokens, themes, header, explorer, focus ring, and responsive navigation.
2. `03-UI-SPEC.md` is canonical for Query dirty state, editor replacement confirmation, status announcements, and responsive mode preservation.
3. This contract specializes that system for ER-01..05 and the decisions in `04-CONTEXT.md`.
4. Graph and list are views of the same normalized relationship model; neither React Flow nor ELK may define product truth.

## Design System

| Property | Value |
|---|---|
| Tool | Manual TinyCrafts CSS token system; no shadcn |
| Preset | Not applicable |
| Component library | None; React Flow is the canvas adapter and `react-resizable-panels` is a layout primitive only |
| Layout engine | ELK in a dedicated lazy worker; one opinionated `Arrange diagram` action |
| Icon library | Inherited inline SVG set; every icon control has visible text or accessible name |
| Fonts | Self-hosted Inter for prose/actions; JetBrains Mono for table/column names, rules, counts, and relationship pairs |
| Shape | 1px rules, 6px controls, 7px node cards; no floating glass, large gradients, or decorative illustration |

No diagram authoring kit, Tailwind, registry block, minimap dependency, custom layout algorithm, animation library, or general graph state framework may be added. A minimap is excluded from v1 unless Phase 4 measurement proves it materially improves navigation without accessibility or bundle regression.

## Spacing Scale

Phase 1 owns spacing values. This phase uses only `--space-1`, `--space-2`, `--space-4`, `--space-6`, `--space-8`, `--space-12`, and `--space-16`. Map compact badge/edge-label gaps to `--space-1` or `--space-2`; map toolbar gaps, node horizontal padding, panel/card padding, and alerts to `--space-4`. There is no 12px layout spacing token.

Exceptions: 1px rules, 2px focus outline, 36px inherited grid, 28px node rows, 40px node headers/toolbars, and 44px coarse-pointer/mobile targets.

## Typography

Use exactly two weights: 400 and 600. No italics.

| Role | Size | Weight | Line height | Use |
|---|---:|---:|---:|---|
| Micro/meta | 12px | 600 | 1.35 | Badges, relationship rules, counts, canvas scale |
| Body/control | 14px | 400 | 1.5 | Inter; buttons/actions, explanations, and prose |
| Schema/data | 14px | 400 | 1.45 | JetBrains Mono; table/column names, ordered pairs, list metadata, counts, timings, and rules |
| Section heading | 18px | 600 | 1.25 | ER, Relationships, and state headings |
| Workspace title | 24px | 600 | 1.2 | Inherited ER mode/page title only |

Node names may truncate visually at one line but expose the full name in accessible text and the inspector. Relationship pairs wrap in the list; they never truncate away a participating column.

## Color and Theme

Phase 1 owns every light/dark value. This phase references semantic names only:

| Usage | Required inherited tokens |
|---|---|
| Surfaces | `--paper`, `--paper-2`, `--paper-3` |
| Names, prose, visible counts/rules/metadata | `--ink`, `--ink-2` |
| Decorative grid/rules only | `--ink-3`, `--rule` |
| Meaningful node, list, sheet, dialog, and control boundaries | `--boundary` |
| Focus | `--focus-ring` |
| Primary fill/on-fill | `--accent`, `--on-accent` |
| Accent text in both themes | `--accent-deep` |
| Selection surface | `--accent-soft` with `--boundary` |
| Error/destructive | `--danger`, `--danger-soft`, `--on-danger` |
| Unresolved/limited/layout warning | `--warning`, `--warning-soft`, `--on-warning` |
| Resolved/success | `--success`, `--success-soft`, `--on-success` |

`--ink-3` and `--rule` are decorative only. Visible relationship counts, table kinds, column types, rules, zoom values, and metadata use at least `--ink-2`. Meaningful nodes, controls, handles, list rows, sheets, and dialogs use `--boundary`; accent-colored text uses `--accent-deep`, including in the light theme. `--accent` is reserved for the active ER/Relationships mode, search match, selected graph/list entity, `Generate join`, and active canvas controls, while focus always uses `--focus-ring`. Default edges use `--ink-2`; unresolved edges use the warning family, are dashed, and are labelled `Unresolved`.

Acceptance must assert 4.5:1 for normal text and 3:1 for meaningful nodes, edges, handles, focus, selection, and control boundaries in both themes. Tests explicitly cover `--ink-2` metadata, `--accent-deep` text, `--boundary` on each surface, and every semantic foreground/background/on-color combination; only the grid and truly decorative rules may be lower contrast.

## Responsive ER Layout

### Wide desktop — 1440px and wider

- Retain the inherited app header and 280px starting catalog rail (resizable 240–360px).
- ER main area uses a horizontal split: diagram 68%, structured Relationships panel 32%, with minimums 520px and 340px. Divider is keyboard-resizable and may range 55–78%.
- A 56px ER command bar spans both panes: `ER diagram`, exact relationship count, search, scope, `Arrange diagram`, and `Fit diagram`.
- Diagram fills available height. Relationship panel has its own heading/filter summary and vertical scroll; the document does not scroll horizontally.
- Selecting in either pane synchronizes visible selection in the other. DOM focus does not move unless the user activates `Focus diagram` or `Show in relationships`.

### Compact desktop — 1024–1439px

- Catalog starts at 240px. Diagram uses the main width; Relationships opens as a persistent 360px side panel when selected and may be hidden with the always-visible `Relationships ({n})` toggle.
- Search and scope remain visible. `Arrange diagram`, `Fit diagram`, zoom controls, and view toggle may occupy a second 40px toolbar row; no action is hidden in a hover-only menu.
- Node inspector uses the same Relationships panel rather than a second overlay.

### Tablet — 768–1023px

- Catalog is the inherited 320px drawer.
- Use an ARIA tab switch immediately below the header: `Diagram` and `Relationships ({n})`. Only the active view occupies the main area; both preserve scroll/selection state.
- Relationships is the default when the graph is over threshold, layout failed, or the canvas capability is unavailable. Otherwise remember the user's last active ER view as non-database-identifying UI preference.
- Diagram command bar is two rows: search/scope then Arrange diagram/Fit diagram/zoom. Canvas height is the viewport remainder and never pushes controls off-screen.
- Node/edge details open as a 360px modal side sheet with focus trap.

### Mobile — below 768px, verified at 375px

- `Relationships` is the default and first tab; `Diagram` is opt-in and lazy-loaded. This guarantees a useful primary path before canvas cost.
- Relationship search and exact count are sticky below the inherited compact header. Cards are one column with 16px gutters and 44px actions.
- Diagram occupies the remaining viewport under a two-row sticky toolbar. Pan/zoom is contained to the canvas; the page itself never pans or overflows horizontally.
- Node/edge detail is a full-screen dialog. `Back to relationships` is always visible, and switching views restores the last focused stable relationship/node when it still exists.
- Pinch zoom and pointer pan work, but every action also has a named 44×44px control. No workflow requires drag, hover, wheel, or multi-touch.

At 200% zoom, use the next narrower layout. The structured list remains available even when React Flow or the layout worker cannot load.

## ER Information Architecture

1. Top-level workspace mode: `ER`.
2. Command bar: relationship count, table/column search, graph scope, Arrange diagram, Fit diagram, zoom controls.
3. Diagram view: bounded graph, selection, node/relationship detail.
4. Relationships view/panel: exact searchable structured representation and join action.
5. Persistent state/status region: full graph, selected subgraph, arranging, warning, unresolved count, or failure.

Search is one shared query over exact table names, column names, and relationship pairs. It filters/highlights both graph and list from the same result IDs. Search never changes the underlying relationship count.

## Table Node Contract

- Default node width is 240px desktop and 216px tablet/mobile; header is 40px and each column row is 28px. Node maximum rendered height is 320px.
- Header shows exact table/view name, type text, and unresolved-count indicator where applicable. Virtual/shadow/view kinds are named; do not represent them by color alone.
- Column rows show name, declared type when present, and text badges: `PK`, `FK`, `UQ`, `GEN`, `HID`. Composite key order appears as `PK 1`, `PK 2` and relationship detail preserves FK pair order.
- Render at most 9 column rows in an unselected node. Prioritize all columns participating in visible relationships, then PK/unique columns, then schema order. `+{n} more columns` opens details; it never implies omitted relationships.
- If more than 9 participating columns exist, show the first 8 plus `+{n} relationship columns`; the selected relationship/list always shows every ordered pair.
- Selected node uses `--accent-soft` fill and a 2px `--boundary` border without changing dimensions. Search match uses a 2px inset `--accent` mark; current selection remains distinguishable with the text `Selected` in its accessible name.
- Handles are at least 16px visually and 24px hit area. They are not independent keyboard stops.

## Relationship Edge Contract

- Direction is child → referenced parent, with the arrowhead at the parent. A persistent legend states this convention.
- One declared FK constraint is one edge regardless of composite column count. Default label is `FK` or `FK · {n} columns`; exact pairs and rules live in selection detail/list.
- Parallel FKs remain separate with stable offsets and distinct relationship ordinal labels. Self references use a visible self-loop. Cycles retain normal direction arrows.
- Selected edge is 3px `--accent` with a `--paper`-backed label; unselected resolved edges are 1.5px `--ink-2`. Increasing stroke width must not cause layout movement.
- Unresolved edges are 2px dashed warning lines ending at a bounded placeholder node labelled `Missing: {target}`. Accessible text includes `Unresolved foreign key` and all known child-side columns.
- Pointer selection of an edge updates the matching list item and inspector. Keyboard users select the same relationship from the selected node's relationship summary or the structured list; edges themselves are not forced into a long tab sequence.
- Decorative crossing/route effects are excluded. Edge animation is prohibited in all motion modes.

## Structured Relationships Contract

- This is a feature-equivalent workflow, not a fallback summary. It derives from the same edge IDs and displays the same exact total.
- Group by child table in stable schema order. Within a group use FK declaration order. Search can match child, parent, or participating columns while preserving original order.
- Render 50 relationships per page; no virtualization dependency. Header reads `Relationships — {matching} of {total}` and the pagination uses the Phase 3 focus contract.
- Each relationship card/row shows:
  1. `{child table} → {parent table}` or `{child table} → Missing: {target}`.
  2. Ordered numbered pairs, each rendered `{child column} = {parent column}`; implicit parent PK is labelled `Referenced primary key` once resolved.
  3. `On update`, `On delete`, and `Match` rule text.
  4. `Resolved` or `Unresolved` with explanatory icon/text.
  5. `Focus diagram` and `Generate join` actions; unresolved joins are disabled with inline reason.
- Composite, self, cyclic, parallel, quoted, and missing-parent relationships use the same card structure. Do not collapse composite pairs into a comma string that loses order.
- Activating a list row selects the matching graph edge but retains list focus. `Focus diagram` explicitly switches/focuses the child node and announces the selected relationship.

## Graph Scope, Scale, and Layout States

### Canvas admission and list-only fallback

The diagram may render only when the selected scope passes every independent admission budget:

1. Node count is at most 75, either for the whole database or for the selected connected subset.
2. Declared relationship edge count is at most 600.
3. The encoded ELK layout request is at most 2 MiB and the encoded ELK layout response is at most 2 MiB.
4. Both projected and actual canvas DOM counts are at most 4,000 elements.

Admission is fail-closed. A deterministic preflight checks nodes, edges, request bytes, projected response bytes, and projected DOM before either React Flow or ELK is instantiated. The worker checks the encoded response and the UI checks actual DOM before publication. If any budget fails, SeeQLite publishes no canvas or partial graph, terminates/discards any unpublished worker result, and keeps the complete structured relationship list usable. Limits are not pooled: spare capacity in one budget cannot offset a breach in another.

Each budget breach enters one exact list-only state:

| Reason code | Exact heading | Exact body | Actions | Initial/restored focus |
|---|---|---|---|---|
| `node_limit` | `Choose a table to map` | `Whole-database diagrams are limited to 75 tables. Choose a table to map up to 75 connected tables.` | `Choose a table`, `Open relationships` | Focus the `Relationships` heading when the state first enters. `Choose a table` then focuses the search/table chooser. |
| `edge_limit` | `Too many relationships to diagram` | `This scope has {edgeCount} declared relationships. Diagrams are limited to 600 relationships. Use Relationships or choose another table.` | `Open relationships`, `Choose another table` | Focus the `Relationships` heading and preserve the selected relationship when it still exists. |
| `layout_payload_limit` | `Diagram data is too large` | `This diagram would exceed the 2 MiB layout-data limit. Use Relationships or choose another table.` | `Open relationships`, `Choose another table` | Focus the `Relationships` heading and preserve the selected relationship when it still exists. |
| `dom_limit` | `Diagram would be too dense` | `This diagram would exceed the 4,000-element rendering limit. Use Relationships or choose another table.` | `Open relationships`, `Choose another table` | Focus the `Relationships` heading and preserve the selected relationship when it still exists. |

The reason code remains machine-readable in application state, diagnostics, and a `data-limit-reason` attribute only. Visible persistent status and the polite live region expose the exact human-readable heading/body and relevant counts, never the internal code. The list continues to show the exact total relationship count and every bounded catalog relationship, including relationships outside the rejected diagram scope. There is no hidden retry or automatic budget relaxation. A budget state is re-evaluated only after the user changes scope; after `Choose a table` or `Choose another table`, all four budgets are evaluated again before diagram code loads.

### Whole graph after admission

- At 1–75 nodes, first ER activation requests one ELK layout and fits the result once. Later visits preserve the session's pan/zoom until schema/subset changes or `Fit diagram` is activated.
- Status copy: `Showing all {n} tables and {r} declared relationships.`
- `Arrange diagram` recomputes positions only. It does not change scope or selection.

### Node-limited schema and connected subset

- Above 75 nodes, enter the exact `node_limit` list-only state; do not instantiate a whole-database diagram.
- Search/selecting a table creates a deterministic breadth-first connected subgraph capped at 75 nodes. Banner: `Showing {shown} of {connected} tables connected to {table}.`
- If the connected component exceeds the cap, state `The nearest 75 tables are shown. Choose another table to change the view.` Re-evaluate edge, layout request/response, and projected/actual DOM budgets for that 75-node subset before diagram admission. Do not offer an unbounded “show all” override.
- The relationship list still exposes all bounded catalog relationships and clearly labels whether a relationship is outside the current diagram scope.

### Empty and failure states

| State | Exact heading/body | Actions |
|---|---|---|
| Empty schema | `No tables to diagram` / `Open a database with tables to use the ER view.` | `Open database` |
| Tables, no FK | `No declared relationships` / `SeeQLite only shows foreign keys defined in SQLite. It does not infer links from column names.` | `View tables` |
| Arranging | `Arranging {n} tables…` / `The relationship list is ready while the diagram is laid out.` | `Open relationships` |
| Layout timeout/failure | `The diagram could not be arranged` / `Relationship data is still available. Try arranging again or use the structured list.` | `Retry diagram layout`, `Open relationships` |
| Canvas chunk failure | `The diagram could not load` / `Use Relationships to inspect every declared foreign key.` | `Retry diagram`, `Open relationships` |
| Unresolved relations | `{n} unresolved relationships` / `The database references tables or columns that could not be resolved. Known declarations are still shown.` | `Review unresolved` |
| Database replaced | `Updating relationships…` | Navigation only until current generation is ready |

Layout failure never clears the shared relationship list, blocks Query, or retries automatically. A stale generation/layout result produces no UI or announcement.

## Canvas Controls and Keyboard Contract

- Named controls: `Zoom in`, `Zoom out`, `Fit diagram`, `Arrange diagram`, and `Reset to whole graph` only when whole graph is allowed. Display current zoom percentage as text.
- Canvas has one labelled entry point: `ER diagram, {n} tables, {r} relationships`. Tab enters the selected/first node; tab again leaves to the inspector/control sequence rather than visiting hundreds of nodes.
- Within canvas node navigation, Arrow keys move to the closest node in that spatial direction; Enter opens node detail; Space selects; Escape clears selection and returns to the canvas entry point.
- When a node is selected, its inspector provides a keyboard list of incoming/outgoing relationships. Selecting one synchronizes the corresponding edge/list item.
- `Arrange diagram`/`Fit diagram` retain focus on the invoking control. Completion announces `Diagram arranged` or `Diagram fitted`; it does not move focus to the canvas.
- Search field: Enter selects the first exact/prefix match, Arrow Down opens the bounded match list, and Escape clears search after first closing the list. The match count is announced politely.
- Pointer pan uses background drag; node drag is disabled in v1 because persisted/manual diagram authoring is out of scope. Wheel/pinch zoom never captures page scrolling until the canvas has focus or active pointer interaction.
- React Flow attribution/licensing requirements remain visible where required and must be themed legibly.

## Selection and Detail Contract

- Node detail contains exact name/kind, flags, all columns in schema order, indexes summary, incoming/outgoing relationships, and `Open in Query` only through Phase 2's safe quoted action.
- Edge detail contains exact child/parent, all numbered column pairs, update/delete/match rules, resolved status, and `Generate join` when resolved.
- The dismiss action is `Close details`. It returns focus to the initiating node, relationship row, or toolbar control by stable ID. If replacement removed it, focus the ER heading and announce the change.
- Visual synchronization scrolls the counterpart into view only when requested or when it is already near the viewport. It never steals focus or unexpectedly changes the user's list page.

## Generate-Join Contract

- Resolved relationship action label is `Generate join`. Unresolved action stays visible but disabled with `Join unavailable because the referenced table or columns could not be resolved.`
- Generated SQL preview shows every ordered pair and deterministic aliases before replacement confirmation. Identifiers display in JetBrains Mono and remain escaped text.
- If the Query editor is empty, insert SQL, switch to Query, focus the first editable SQL position, and announce `Join query added for {child} and {parent}.`
- If Query is dirty, open a modal:
  - Title: `Replace current SQL?`
  - Body: `Generating this join will replace your unsaved SQL. Query history is not a draft backup.`
  - Read-only preview label: `Generated join`
  - Default action: `Keep current SQL`
  - Destructive action: `Replace with join`
- Choosing `Keep current SQL` or dismissing the confirmation retains editor text, ER selection, list/canvas position, and focus returns to `Generate join`.
- Replacement never occurs from hover, selection, or `Focus diagram`; only the explicit confirmed action may replace a dirty draft.

## Focus, Status, and Accessibility Contract

- Landmarks: ER command bar → Diagram → Relationships. Each has a heading and skip target. On single-view tablet/mobile, the ARIA tab controls the labelled panel.
- Relationship count, selected item, unresolved count, subset scope, layout start/completion/failure, search match count, and join handoff have concise live announcements. Pan and zoom changes are not continuously announced; explicit zoom controls announce the final percentage.
- The relationship list is present and functional when canvas scripts, WebGL/canvas-adjacent capabilities, ELK, or layout fail. It is included in keyboard and screen-reader acceptance, not hidden behind an error-only path.
- PK/FK/UQ/GEN/HID, resolved/unresolved, child/parent direction, selected/search match, and subset state all include text/shape semantics independent of color.
- Every visible focus target uses a 2px `--focus-ring` outline with 4px offset. Where canvas or scroller clipping would cut it off, use the Phase 1 equivalent: a non-layout-shifting pseudo-element inset 4px with a 2px `--focus-ring` border.
- Dialogs/sheets follow the Phase 3 trap, Escape, default-safe-action, and focus-restoration contract.
- Screen-reader node names stay bounded: announce table name, kind, column count, incoming/outgoing relationship counts, and selection; read full columns only in detail/list, not in every node label.

## Motion

- Initial/Arrange layout position transition may run 180ms ease-out; selection transitions 120ms. Edge path drawing and continuous motion are prohibited.
- Under reduced motion, node positions update immediately, `Fit diagram` jumps without smooth zoom, sheets do not translate, and static status text replaces spinners.
- Search, selection synchronization, and focus movement do not depend on animation completion.

## Objective Acceptance Checks

### Truth and state equivalence

- [ ] For every golden fixture, diagram and structured list expose identical relationship IDs/counts, ordered pairs, rules, and resolution state; composite FKs are one edge.
- [ ] Name-like columns without declared constraints create no edge, label, count, or generated join.
- [ ] Self, cycle, parallel, implicit-parent, quoted, Unicode, composite, and missing-parent fixtures render/announce without data loss or crashes.
- [ ] Every graph scope says all/subset and shown/total counts; no schema above the threshold instantiates or arranges an unbounded whole graph.

### Visual and responsive

- [ ] Light/dark screenshots at 375, 768, 1024, 1280, and 1600px cover full graph, selected edge/node, connected subset, no-FK, unresolved, arranging, layout failure, and each distinct `node_limit`, `edge_limit`, `layout_payload_limit`, and `dom_limit` list-only state. Captures verify exact human-readable copy/actions/focus, no partial canvas, and continued relationship-list access; internal reason codes appear only in diagnostic attributes.
- [ ] Nodes are 240/216px as specified, remain within 320px height, show text badges, and retain readable selected/focus states without layout shift.
- [ ] Default/selected/unresolved edges, arrowheads, handles, and meaningful boundaries meet 3:1 in both themes; all normal text meets 4.5:1.
- [ ] Diagram, list, sheets, and dialogs never cause page-level horizontal overflow at normal or 200% zoom.

### Keyboard and assistive technology

- [ ] A keyboard-only user can search/select a table, navigate a connected diagram, inspect incoming/outgoing relations, switch to the list, inspect every ordered pair/rule, and generate a join without dragging.
- [ ] Canvas failure/timeout still permits the complete relationship-list workflow and join generation.
- [ ] Arrange diagram/Fit diagram/search/selection/view-switch/dialog/replacement focus and announcements match this contract; synchronization never steals focus.
- [ ] Axe reports no serious/critical violations in both themes at representative mobile/tablet/desktop widths, and manual NVDA/VoiceOver checks understand child→parent direction and composite order.

### Scale, recovery, and handoff

- [ ] 0, 1, 25, 75, 150, and 500-node fixtures activate the specified empty/full/subgraph behaviors without a release-budget main-thread stall.
- [ ] Canvas renders only when node ≤75, edge ≤600, encoded request and response each ≤2 MiB, and projected and actual DOM each ≤4,000; every breach uses its exact reason/copy/actions/focus contract with no partial graph or hidden retry.
- [ ] Layout worker crash, timeout, duplicate response, schema replacement, and rapid `Arrange diagram` cannot publish stale positions or disable Query/Relationships.
- [ ] Relationship list pages contain at most 50 relationships and preserve focus after page/search changes.
- [ ] Generated joins include every ordered pair and quoted identifier; unresolved joins are disabled; dirty SQL never changes without explicit confirmation.
- [ ] Reduced-motion mode removes layout/zoom/sheet animation while retaining selection and status clarity.

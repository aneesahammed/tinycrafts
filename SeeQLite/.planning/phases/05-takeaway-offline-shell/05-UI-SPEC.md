# Phase 5 — UI Design Contract

> Visual and interaction contract for bounded export and the repeat-offline application shell. Generated by gsd-ui-researcher and independently verified by the GSD UI checker.

## Sources and Inheritance

- Inherit the complete manual TinyCrafts token, typography, spacing, focus, and action-copy system established in Phase 1. Phase 5 defines component usage only; it must not add or redefine global visual tokens.
- Product behavior is locked by `PROJECT.md`, `REQUIREMENTS.md` EXP-01..03 and OFF-01..03, `ROADMAP.md`, `research/SUMMARY.md`, and `05-CONTEXT.md` decisions D-36..D-43.
- The canonical visual source is the TinyCrafts landing page: warm paper surfaces, restrained 36px grid, compact 6–7px radii, square-edged catalogue details, direct lowercase-friendly copy, and equal-quality light and dark themes.
- No shadcn initialization or registry lookup is permitted. This is an explicit manual-system decision, not an unresolved design-system gap.

## Design System

| Property | Value |
|----------|-------|
| Tool | Manual TinyCrafts CSS custom-property system inherited from Phase 1 |
| Preset | Not applicable |
| Component library | None; use semantic HTML and existing project primitives |
| Icon library | None; use a minimal set of audited same-origin inline SVGs with `aria-hidden="true"` when adjacent text supplies the name |
| Font | Phase 1 contract: self-hosted Inter for prose, headings, and actions; JetBrains Mono for SQL, identifiers, values, counts, timings, and metadata |

### Component rule

Phase 5 may add only four UI primitives: `ExportDisclosure`, `RuntimeStatus`, `UpdateNotice`, and `ConfirmDialog`. Each is feature-local and composed from native buttons, radio inputs, headings, lists, `<output>`, and `<dialog>` where modal confirmation is required. Do not add a toast system, popover framework, PWA framework, or general component package.

## Spacing Scale

Declared values are the Phase 1 scale and remain multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-label gap, compact metadata |
| `--space-2` | 8px | Inline controls, status icon gap |
| `--space-4` | 16px | Control groups and panel padding on narrow screens |
| `--space-6` | 24px | Desktop panel padding and section separation |
| `--space-8` | 32px | Major workspace separation |
| `--space-12` | 48px | Empty-state vertical rhythm |
| `--space-16` | 64px | Page-level separation only |

**Exceptions:** interactive targets are at least 44×44px; 1px rules are permitted as non-layout decoration; the inherited 36px background grid is decorative and not a spacing token. `12px` is a font size only and is never used for layout spacing, padding, or gap.

## Typography

Use exactly four application text sizes and two weights. Tabular values and counts use `font-variant-numeric: tabular-nums`.

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Data / metadata | JetBrains Mono | 12px | 600 | 1.33 |
| Body / action | Inter | 14px | 400 | 1.5 |
| Section heading | Inter | 18px | 600 | 1.25 |
| Panel display | Inter | 24px | 600 | 1.2 |

Do not use italics, all-caps paragraphs, or font weight as the only state distinction. Uppercase is reserved for short metadata labels and may use the inherited letter spacing.

## Color

All color values come from the canonical Phase 1 semantic tokens; Phase 5 defines no hex, RGB, or component-local color.

| Role | Canonical token usage |
|------|-----------------------|
| Dominant (60%) | `--paper` for the workspace and export/offline field |
| Secondary (30%) | `--paper-2` for quiet status bands and `--paper-3` for export panels/dialogs |
| Essential text | `--ink` for headings and `--ink-2` for visible body copy, status, counts, and metadata |
| Decorative text | `--ink-3` for non-text decoration only; all visible placeholders, status, and metadata use `--ink-2` |
| Meaningful boundary | `--boundary` for controls, inputs, dialogs, notices, and any edge needed to perceive a component |
| Decorative rule | `--rule` for non-essential dividers only |
| Accent fill/selection | `--accent` with `--on-accent` for the primary export action, selected format, and progress |
| Focus | `--focus-ring` for every keyboard focus outline/inset equivalent |
| Accent text/link | `--accent-deep`, including light-theme actionable text; never `--accent` as small text on paper |
| Failure/destructive | `--danger`, `--danger-soft`, and `--on-danger` |
| Warning/limited | `--warning` and `--warning-soft` |
| Ready/success | `--success` and `--success-soft` |

Accent is reserved for focus, the selected export format, the download action, and an actionable update control. Warning/success/destructive colors never carry meaning without text and an icon. Automated assertions must prove 4.5:1 ordinary text contrast and 3:1 meaningful boundary/focus contrast for every token pairing in both themes; a failed assertion blocks release rather than adding a Phase 5 color.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Export displayed rows` |
| Format CTA | `Download CSV` or `Download JSON`, matching the selected format |
| Empty state heading | `Nothing to export` |
| Empty state body | `Run a query to create a result. SeeQLite exports the bounded result it already holds; it does not run the query again.` |
| Export error | `SeeQLite could not prepare this download. Your result is unchanged. Use Retry export or choose the other format.` |
| Offline fallback | `Offline setup is unavailable. Online database work still works.` |
| Destructive confirmation | `Reset offline copy? This removes only cached SeeQLite app files. It does not clear query history or affect other TinyCrafts tools. You will need internet to make SeeQLite available offline again.` Buttons: `Keep offline copy` and `Reset offline copy`. |

### Required scope and hardening copy

- Complete held result: `Exports all {heldRows} rows and {columnCount} columns currently held by SeeQLite — not only this {pageRows}-row page.`
- Truncated held result: `This result is limited. The export contains {heldRows} held rows and {columnCount} columns. It does not contain data beyond: {truncationReasons}.`
- Zero-row result: `This result has 0 rows and {columnCount} columns. CSV includes the headers; JSON includes the columns and an empty rows list.`
- CSV disclosure: `CSV is designed for spreadsheets and is lossy. NULL is exported as an empty field, and formula-like text is prefixed with a single quote. Choose JSON when exact types and values matter.`
- JSON disclosure: `JSON preserves column order, duplicate labels, tagged integers, BLOB previews, and truncation metadata.`
- Offline-ready: `Ready offline — the app shell is stored on this device. Databases are not stored.`
- Currently offline: `Offline — choose a local database to continue. A previous database will not reopen automatically.`
- Update ready: `A complete SeeQLite update is ready. Reload when you are ready to close the current database.`
- Update failed: `The update could not be completed. SeeQLite is using the last complete offline version.`
- Storage full: `SeeQLite could not prepare offline use because browser storage is full. Online use still works.`
- Unsupported service worker: `Online only — this browser does not support SeeQLite's offline shell.`

Copy must say `prepared` rather than `downloaded` after object-URL activation because the browser does not expose reliable save completion. Never claim CSV is universally safe, that an offline database is retained, or that an update has installed before the complete asset set succeeds.

## Export Interaction Contract

### Entry point and layout

1. Place `Export displayed rows` in the result toolbar after result counts/truncation and before secondary result actions. It is disabled only when there is no current held result or while a download is being prepared.
2. Activation reveals `ExportDisclosure` in normal document flow immediately below the result toolbar. Do not use a hover popover or toast. The region is a labelled `<section>` and remains visible until the user closes it, replaces/closes the database, or explicitly starts another query.
3. The first line is the exact scope sentence. If any result dimension is truncated, the warning follows immediately and is visible without expanding another control.
4. Present CSV and JSON as a native radio group with a short outcome description. Default to JSON when the held result contains BigInt, BLOB, duplicate labels, truncated values, or dynamic mixed types; otherwise default to CSV. The default is deterministic and never changes after the user manually chooses.
5. The primary button label changes with the radio selection. A secondary `Close export` button follows. Do not create a format split-button.

### Export state model

| State | Visible contract | Enabled actions | Announcement/focus |
|-------|------------------|-----------------|--------------------|
| No current result | Toolbar action disabled; adjacent helper text available through `aria-describedby` | None | No live announcement |
| Ready, complete | Counts, page-vs-held distinction, format radio group | `Download CSV`/`Download JSON`, `Close export` | On open, focus selected format radio |
| Ready, truncated | Same plus persistent warning listing every active truncation cause | `Download CSV`/`Download JSON`, `Close export` | Warning is part of region description, not an interrupting alert |
| Zero rows | Header/column count and format-specific zero-row outcome | `Download CSV`/`Download JSON`, `Close export` | Same as ready |
| Preparing | Button label `Preparing {FORMAT}…`; both format choices and repeated export disabled | `Close export` remains disabled until the synchronous snapshot is captured; no stop-export action is promised | Polite `role="status"` once |
| Prepared | Inline output `Download prepared: {filename}`; result remains | `Prepare another export`, `Close export` | Polite announcement; focus stays on the initiating button |
| Failed | Persistent inline `role="alert"` with bounded normalized reason; result remains | `Retry export`, switch format, `Close export` | Alert announced once; focus moves to error heading only if the failure followed a blocking dialog |
| Result invalidated | Disclosure closes, export becomes disabled, stale result cannot be downloaded | None | Focus returns to the nearest surviving result/workspace heading |

### CSV contract exposed by the UI

- The encoder uses UTF-8, CRLF records, one header row, RFC 4180 quoting, and the held positional row order.
- `NULL` becomes an empty field. Empty text also parses as empty in CSV; disclose this loss and point to JSON for exact values.
- Only SQLite text values receive formula hardening. A text value is formula-like when its first code point is `=`, `+`, `-`, `@`, tab, CR, or LF, or when one of `=`, `+`, `-`, `@` follows a leading run of ASCII space/control characters. Prefix one ASCII apostrophe to the original, otherwise unmodified, text before CSV quoting.
- Numeric values are encoded as numeric text; BLOB and truncated values use deterministic human-readable markers that include original byte length and the fact that only a preview is present.
- The disclosure must remain visible before every CSV preparation, including repeat downloads.

### JSON contract exposed by the UI

- Download a deterministic `{ columns, rows, metadata }` object with positional rows. Never key rows by duplicate column labels.
- Tagged BigInt, BLOB, and truncated values are described in the JSON help copy; the UI must not call the representation native SQLite binary.
- The metadata repeats held row/column counts, all truncation causes, query duration, and export schema version. It does not contain a file path or full database fingerprint.

### Filename and object URL

- Suggested name: `{sanitizedDatabaseStem}-result-{YYYYMMDD-HHmmss}.{csv|json}`. Remove path separators, control/bidi formatting characters, leading dots, and trailing spaces; collapse repeated separators; cap the stem at 80 Unicode code points; fall back to `seeqlite-result`.
- Create one object URL per preparation, activate it once, and revoke it after the click task. Repeated activation while preparing is disabled. Failure to create/click/revoke yields the failure state without clearing the held result.

## Offline, Install, and Update Contract

### Placement

- A compact `RuntimeStatus` sits in the existing application header utility area on widths ≥768px and on its own full-width row beneath the workspace tabs below 768px.
- Normal states (`Online`, `Ready offline`, `Offline`) use one icon, one short label, and optional secondary action. They must not consume a modal or toast.
- Actionable exceptions (`Update ready`, setup failed, cache quota, version mismatch) render as a durable `UpdateNotice` immediately beneath the application header. The notice persists until resolved or explicitly dismissed where dismissal is safe.

### State hierarchy

| Priority | State | Copy/action |
|----------|-------|-------------|
| 1 — blocking | Required offline asset missing while currently offline | `This offline copy is incomplete. Connect to the internet to restore SeeQLite.` No file intake is offered if the engine cannot load. |
| 2 — action required | Complete update waiting | Update-ready copy; `Review update` and `Keep current version` |
| 3 — degraded warning | Registration/cache/quota/update failure while online | Exact failure-family copy; core work remains enabled; use `Retry offline setup` or `Retry update` only after a user action or connectivity change |
| 4 — progress | Preparing offline use or downloading a complete update | `Preparing offline use…` / `Preparing update…`; no percentage unless actual byte progress exists |
| 5 — ready | Current shell is fully cached | `Ready offline — databases are not stored.` |
| 6 — neutral | Online, no installed shell evidence | `Online`; optional `Install app` only when the browser exposes an install prompt |

### Install behavior

- Show `Install app` only when the browser exposes a valid install-prompt event. Absence of that event is not an error and must not trigger UA-sniffed instructions.
- If the prompt is accepted, keep status at `Preparing offline use…` until the complete versioned asset set is verified. If dismissed, return to neutral without nagging.
- Manifest-only installation (for browsers with their own UI) remains supported without an in-app prompt. The privacy/limits copy explains that installation stores application assets, not databases.

### Update behavior

- Never auto-reload an active tab. A waiting worker produces `Update ready` in every controlled tab.
- `Review update` opens `ConfirmDialog`: `Reload SeeQLite to update? The current database, result, and unsaved workspace state will close. Your database is not stored and will not reopen automatically. Query history already saved in this browser remains.` Buttons: `Keep current version` and `Reload SeeQLite`.
- If the SQL draft is dirty, include a secondary `Copy SQL` action and confirm copy success inline before enabling `Reload SeeQLite`; `Keep current version` returns focus to `Review update` and leaves the complete old version active.
- An interrupted or incomplete new cache never shows `Update ready`; show the update-failed copy while the old complete version continues.
- `Reset offline copy` lives under the existing Help/Privacy utility, not in the primary header. It always requires the destructive confirmation copy above and never clears localStorage/history or any non-`seeqlite-*` cache.

### First-ever offline truthfulness

An application that has never completed an online load may not have enough assets to render its own error. Public help/landing release copy therefore says: `First use needs an internet connection. After one complete visit, the SeeQLite app can reopen offline; you still choose the database file each time.` A previously cached but currently incomplete shell uses the blocking state above.

## Keyboard, Focus, and Announcement Contract

- `Export displayed rows` opens the section and focuses the selected format radio. `Escape` closes it only when focus is inside the export section and no confirmation dialog is open; focus returns to the trigger.
- Radio choices use arrow-key behavior. Tab order is format → disclosure link/help → primary download → `Close export`. Do not add roving-tabindex logic.
- Preparing and ready status uses one polite live region. A failure uses one atomic alert. Re-renders may not repeat identical announcements.
- The update notice enters the document after the header but never steals focus. When a user activates `Review update`, the dialog receives focus at its heading/first safe action; `Escape` or `Keep current version` returns focus to `Review update`.
- The destructive reset dialog defaults focus to `Keep offline copy`, not the destructive action.
- If an update/error causes a control to disappear, focus moves to the runtime-status heading or nearest surviving workspace heading, never to `<body>`.
- Every icon-only affordance has a visible tooltip on hover/focus and an accessible name, but Phase 5 actions should use visible text wherever space permits.

## Accessibility Contract

- Export scope, truncation, CSV mutation, JSON typing, and offline database non-persistence must be available as text, not tooltip-only content.
- The disclosure is a labelled region; the format choice is a `<fieldset>`/`<legend>`; counts are text with tabular numerals; warnings use lists when multiple truncation reasons exist.
- All statuses have name, role, and state; success is `role="status"`, user-blocking failure is `role="alert"`, and dialogs have an accessible name and description.
- Respect `prefers-reduced-motion`: no sliding notice, progress shimmer, pulsing offline icon, or animated format switch. A static spinner icon may rotate only when motion is allowed and must include visible progress text.
- Meet WCAG 2.2 AA: 4.5:1 normal text, 3:1 large text and meaningful `--boundary`/focus edges, a global 2px `--focus-ring` outline with 4px offset (or inset 2px equivalent when clipped), 44px touch targets, and no keyboard trap.
- At 200% zoom and 375px CSS width there is no page-level horizontal scroll; only the existing result grid may scroll horizontally inside its labelled region.

    - Fetch serves exact current manifest members first; when an old tab requests a path absent from current, it may serve only an exact member listed in the retained previous complete cache's signed-by-build completion manifest.

Implement D-41/D-42 as a small standalone generated worker plus pure policy helpers. Register install/activate/fetch/message listeners; do not catch-and-continue install errors and do not auto-skip waiting. Prefix-filter before cleanup/reset and retain one prior complete cache. Fetch looks up the current manifest first, then reads the retained previous completion record and may match only an exact previous member/path; never use origin-wide `caches.match`. This lets a tab loaded from the immediately preceding build load a previously unused hashed lazy chunk after activation without accepting arbitrary stale content.

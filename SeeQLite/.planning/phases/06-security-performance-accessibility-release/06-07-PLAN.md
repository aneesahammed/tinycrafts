## Implementation

- Use `PRAGMA table_list` for object kind (including virtual/shadow) and rowid/strict flags; join `sqlite_schema` only for nullable SQL definitions.
- Keep summary columns eager for editor/ER consumers, but move index enumeration to an epoch-guarded `details` worker request.
- Reconcile `PRAGMA index_list` with `sqlite_schema` because SQLite WASM builds can omit explicit expression/partial indexes from the pragma view.
- Derive bounded partial-index predicates from the stored SQLite definition; never execute or inject the definition.
- Preserve searchable object rows when per-object metadata fails or global catalog budgets are reached; disable the ER canvas at the independent 75-table cap.
- Render only a 100-object catalog page at a time, and clear derived query plans whenever a new query or plan operation starts.
- Generate the service worker from the final `dist` tree after Vite output; exclude database/sidecar files and scope activation cleanup to `seeqlite-*` caches.
- Keep the approved 5,000-object/50,000-column catalog limits and authorizer rules; do not add a second catalog endpoint or permit writes.
- Filter only at the presentation boundary; retain one worker catalog for editor completion and relationship resolution.
- Use a checked-in AUTOINCREMENT smoke fixture so SQLite creates a real internal object without changing the visible user-table count.

## Acceptance criteria

- `npm test`, `npm run typecheck`, `npm run build`, and `npm run check:bundle` pass.
- `npm run test:e2e` passes all scenarios in Chromium, Firefox, and WebKit, including the internal-object toggle and CREATE SQL detail check.
- The smoke fixture spans generated/hidden columns plus partial, expression, auto-created, and unique indexes; malformed, virtual, and 5,001-object limited fixtures cover failure isolation, STRICT/WITHOUT ROWID/virtual-shadow flags, and bounded catalog degradation.
- The catalog page never mounts more than 100 object buttons, and the forced-colors/zoom/reduced-motion and stale-plan regressions pass in all three engines.
- Default catalog shows two user tables and an explicit internal-hidden affordance; opting in shows the runtime-provided internal object and marks it `INTERNAL`.
- Toggling off clears an internal selection, preserves a user-table selection, and leaves the ER relationship list resolvable.
- No unbounded SQL/identifier text is introduced into attributes, URLs, CSS, logs, or network requests; metadata remains inert escaped text.
- The generated service worker precache contains the entry, CSS, fonts, workers, WASM, icons, manifest, and lazy chunks; no SQLite/database/sidecar path is cached.

## Failure modes and follow-up

- Empty or unusual databases may have no SQL definition; the details view omits the CREATE disclosure rather than inventing SQL.
- SQLite builds may expose different virtual system rows; tests assert the runtime contract (`sqlite_schema`) and treat absent optional rows as valid.
- CAT-02/CAT-04 now pass the approved virtual/shadow and 5,001-object boundary coverage; exotic virtual modules and low-memory/25–50 MiB measurements remain follow-up evidence.
- OFF-01/OFF-02/OFF-03 are covered by the generated worker, scoped-cache checks, offline shell E2E, and non-blocking registration fallback; manual Safari update/reload remains a host gate.
- Manual Safari/VoiceOver, Windows NVDA, deployed response-header/CSP, measured performance, and DataDuck advisory closure remain release gates.

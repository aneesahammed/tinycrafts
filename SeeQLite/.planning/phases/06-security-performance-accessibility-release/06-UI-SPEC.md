# Phase 6 — UI Design Contract

> Release-level visual, interaction, accessibility, privacy, limitation-copy, and TinyCrafts catalogue contract. Generated by gsd-ui-researcher and independently verified by the GSD UI checker.

## Sources and Inheritance

- Inherit the manual TinyCrafts workspace system established in Phase 1 and all state/component contracts owned by Phases 2–5. Phase 6 audits and fixes; it does not introduce a parallel visual language.
- Product behavior is locked by `PROJECT.md`, `REQUIREMENTS.md` SEC-01..02, PERF-01, A11Y-01, REL-01..02, `ROADMAP.md`, `research/SUMMARY.md`, and `06-CONTEXT.md` decisions D-44..D-52.
- The landing-card contract comes directly from `../index.htm`; preserve its specimen structure, tokens, type, breakpoints, focus/hover behavior, and existing item order.
- No shadcn initialization or registry lookup is permitted. Use existing semantic primitives, plain CSS, and same-origin assets only.

### Phase 6 component rule

The only new application surface allowed is a `PrivacyAndLimitsDialog` opened from the existing Help/utility area. It uses native `<dialog>`, plain lists, and existing button styles. Do not add a settings page, router, toast system, cookie banner, design-system package, or analytics UI. Release evidence pages are documentation artifacts, not production application routes.

## Typography

The application keeps exactly four sizes and two weights. The TinyCrafts landing card retains the host page's existing type rules; it does not create application tokens.

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Data / metadata | JetBrains Mono | 12px | 600 | 1.33 |
| Body / action | Inter | 14px | 400 | 1.5 |
| Section heading | Inter | 18px | 600 | 1.25 |
| Page/panel display | Inter | 24px | 600 | 1.2 |

No italics. All-caps is limited to short metadata. Long privacy/limitation copy uses Inter at 14px/1.5 and a maximum line length of 72ch. Database-derived text uses `dir="auto"`, `unicode-bidi: plaintext`, and bounded wrapping without changing the underlying value.

## Color

All application colors reference the canonical Phase 1 semantic tokens. Phase 6 audits those tokens and must not redefine them with hex, RGB, or component-local values.

| Role | Canonical token usage |
|------|-----------------------|
| Dominant (60%) | `--paper` for viewport/workspace and landing ground |
| Secondary (30%) | `--paper-2` for rails/quiet bands and `--paper-3` for interactive surfaces/dialogs |
| Essential text | `--ink` for headings and `--ink-2` for all visible body copy, status, counts, timings, and metadata |
| Decorative text | `--ink-3` for non-text decoration only; all visible placeholders use `--ink-2` |
| Meaningful boundary | `--boundary` for controls, focus-adjacent edges, dialogs, notices, table/graph affordances, and every edge needed to perceive a component |
| Decorative rule | `--rule` for non-essential separators only |
| Accent fill/selection | `--accent` with `--on-accent` for primary action, selection, and progress |
| Focus | `--focus-ring` for every keyboard focus outline/inset equivalent |
| Accent text/link | `--accent-deep`, including light-theme accent text; never `--accent` as small text on paper |
| Failure/destructive | `--danger`, `--danger-soft`, and `--on-danger` |
| Warning/limited | `--warning` and `--warning-soft` |
| Ready/success | `--success` and `--success-soft` |

Accent is reserved for focus, primary actions, active selection, links requiring action, and the landing specimen hover. Status colors always include a heading, icon, and explicit sentence. Automated contrast assertions must prove WCAG 2.2 AA in both themes and every hover/focus/disabled state: 4.5:1 ordinary text and 3:1 large text, meaningful `--boundary` edges, and focus. A failed assertion blocks release rather than creating a Phase 6 override.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Open SQLite database` |
| Privacy heading | `Your database stays in this tab` |
| Privacy body | `SeeQLite processes your file locally. It does not upload your database, schema, queries, or results. Query history can store bounded SQL in this browser until you clear it.` |
| Unsupported heading | `SeeQLite cannot run in this browser` |
| Unsupported body | `This browser is missing: {capabilityList}. No file has been opened. Use a current version of Chrome, Firefox, Edge, or Safari.` |
| Fatal engine error | `SQLite could not start. No database was opened. Reload SeeQLite once; if the problem continues, use a supported browser and report the shown error code.` Action: `Reload SeeQLite`. |
| Empty/no-FK boundary | `No declared relationships` / `SeeQLite shows foreign keys declared by SQLite. It does not infer links from column names.` |

### Required public limitations copy

The `PrivacyAndLimitsDialog`, release notes, and product help must disclose all of the following in plain language:

1. `Read only — SeeQLite does not edit or save changes to the database.`
2. `One file at a time — opening another database replaces the current session.`
3. `Transient database — the selected database is not stored and will not reopen automatically after reload.`
4. `Declared links only — the ER view shows SQLite foreign keys, not inferred relationships.`
5. `WAL files — choose a checkpointed main database. Uncheckpointed changes held only in -wal/-shm sidecars may be absent.`
6. `Bounded results — query rows, columns, cells, previews, and exports are capped. Every active limit is shown beside the result and in exports.`
7. `Offline shell — after one complete online visit the app can reopen offline, but databases are never cached.`
8. `CSV changes some text — formula-like text is prefixed with a single quote. Use JSON when exact typed values matter.`
9. `Browser support — current Chrome, Firefox, Edge, and Safari with WebAssembly, BigInt, transferable buffers, and module workers.`
10. `Hosting limits — GitHub Pages may not provide every security response header. SeeQLite does not claim header protections that the deployed response does not contain.`

Do not use `completely secure`, `zero risk`, `works in every browser`, `all data stays on your device` without qualification, `full export`, `all relationships`, or `offline database`. Do not expose stack traces, raw exception objects, memory addresses, local paths, or filenames inside telemetry/logging copy.

### Global action-label audit

The release UI uses action+noun labels everywhere: `Reset workspace`, `Reload SeeQLite`, `Run query`, `Build query plan`, `Stop query`, `Stop query plan`, `Arrange diagram`, `Fit diagram`, `Generate join`, `Close export`, and `Close privacy & limits`. Retry labels match their owning phase exactly (`Retry database open`, `Retry editor`, `Retry diagram layout`, `Retry diagram`, `Retry export`, `Retry offline setup`, or `Retry update`). Generic single-word action labels fail the release copy check.

## Privacy and Limits Surface

- Add a visible `Privacy & limits` text button in the existing Help/utility area. It is available before and after a database opens and at every responsive width.
- The native dialog is titled `Privacy & limits`, begins with the proven privacy body, then shows three compact non-color badges: `Local file`, `Read only`, and `Declared links only`.
- Follow with the ten limitation items above, a `Clear query history` action using the Phase 3 confirmation, and a `Close privacy & limits` button. Do not place database-derived content in this dialog.
- On open, focus the dialog heading or `Close privacy & limits` according to the existing dialog primitive. Escape and `Close privacy & limits` return focus to `Privacy & limits`. Background content is inert while modal.
- If the privacy marker suite has not passed in the release pipeline, the production build must not ship the affirmative privacy body; release is blocked rather than silently weakening the copy.

## Unsupported and Degraded Capability Contract

| Condition | Surface | Required outcome |
|-----------|---------|------------------|
| Missing Worker, WebAssembly, BigInt, transferable ArrayBuffer, or module Worker | Full-workspace blocking state before file intake | Show unsupported heading/body with exact missing capabilities; disable/remove picker/drop target; retain Privacy & limits and theme controls |
| Missing optional localStorage | Inline warning | `Query history will last only for this tab. Database work is still available.` |
| Missing service worker/Cache Storage | Inline warning/status | `Online only — offline app files cannot be stored here. Database work is still available.` |
| SQLite worker/WASM asset failure | Blocking engine state | Fatal engine copy, bounded error code, `Reload SeeQLite`; never fall back to main-thread SQLite |
| Catalog/result/graph budget reached | Owning-panel warning | State exact limit and available subset/search action; never freeze, retry silently, or hide the whole workspace |
| Layout worker failure | ER-panel warning | Keep structured relationship list usable; offer `Retry diagram layout` only after explicit action |
| Export/cache/update failure | Owning Phase 5 inline state | Preserve result or last complete shell and use Phase 5 recovery copy |

Blocking states use one page-level `<h1>`, the product identity, missing capability list, recovery action, privacy/help access, and no false disabled workspace behind it. Degraded optional features never use a modal on startup.

## Status Hierarchy

Every asynchronous or exceptional state follows one hierarchy; no important outcome is toast-only.

| Priority | Kind | Role | Placement | Examples |
|----------|------|------|-----------|----------|
| 1 | Blocking product | `alert` after initial render; focus heading | Replaces workspace body | Unsupported browser, SQLite cannot start |
| 2 | Blocking operation | `alert` once; focus only after user-triggered failure where continuation needs it | Top of owning panel | Invalid file, unrecoverable rehydrate, export failure |
| 3 | Persistent warning | Described region; polite announcement on first appearance | Beside affected data/action | WAL caution, truncation, limited catalog/graph, offline-only limitation |
| 4 | Progress | `status` with `aria-busy` on owning region | Beside initiating action and panel heading | Opening, querying, planning, arranging, rehydrating, updating |
| 5 | Ready/success | Short `status`, not a celebratory toast | Stable utility/summary row | Database ready, result returned, offline ready |
| 6 | Neutral metadata | Plain text | Summary/toolbars | Counts, duration, current page, browser/version evidence |

Use direct verbs and stable nouns. Announce each state transition once. Re-rendering elapsed time must not repeat live-region speech. Warnings/errors remain until the affected state is changed, dismissed where safe, or recovered.

## Security and Hostile-Content Rendering Contract

- Filenames, identifiers, schema SQL, defaults, errors, plan detail, relationship labels, values, and export names are untrusted text. Render through React text nodes/native `textContent`; no `dangerouslySetInnerHTML`, HTML-to-React parser, or URL construction from database content.
- Bound visible previews and provide a deliberate `View full bounded value` action where already specified. Never put an unbounded database value in `title`, `aria-label`, live regions, CSS generated content, data attributes used by selectors, URLs, or logs.
- Isolate bidirectional text with `dir="auto"` and `unicode-bidi: plaintext`; expose suspicious control characters through an optional visible escaped representation, not silent removal from the canonical value.
- Correctly quote database identifiers only through the shared SQLite identifier helper. Copy/join actions show what will be inserted and protect dirty SQL.
- CSP error UI shows a stable application error code and recovery guidance, not policy internals that imply a protection the host did not deliver.
- No runtime remote font, image, icon, script, analytics, error collector, or network-dependent help link is introduced in the SeeQLite app.

## Keyboard and Focus Contract

### Global order

1. `Skip to workspace` is the first focusable element; add `Skip to results` only when a current result exists.
2. Product/home, theme, Privacy & limits, runtime status action, primary mode navigation, explorer/search, and active workspace follow visual order.
3. Resizable separators expose separator role, orientation, current/min/max values, arrow-key resize, and a reset shortcut; collapsed panels remain recoverable by keyboard.

### Required focus outcomes

| Event | Focus outcome |
|-------|---------------|
| Picker cancelled | Returns to `Open SQLite database`; no status theft |
| Valid open completes | Explorer/catalog heading receives programmatic focus only when the user initiated open; readiness is also announced |
| File validation fails | Error heading in intake region, then retry/open action |
| `Run query` completes | Result summary receives focus after the keyboard shortcut; pointer activation keeps focus on `Run query` while summary is announced |
| Query/plan error | Owning error heading; editor draft remains reachable next |
| `Stop query` | `Stop query` is removed/disabled, `Query stopped. Reopening database…` is announced; after recovery focus returns to the editor and `Database ready` is announced |
| `Stop query plan` | `Stop query plan` is removed/disabled, `Query plan stopped. Reopening database…` is announced; after recovery focus returns to the editor and `Database ready` is announced |
| Page/sort result | Focus remains on activating control or equivalent cell/heading; page change never resets to body |
| ER edge/list selection | Canvas and structured list synchronize `aria-current`; focus stays in the surface used |
| Join confirmation | `Keep current SQL` returns to `Generate join`; `Replace with join` moves to the editor and announces insertion |
| Export | Phase 5 focus contract applies |
| Responsive breakpoint | Preserve the same semantic target; if hidden, move to active mode tab with a concise announcement |
| Blocking capability state | Focus unsupported heading after initial paint; do not repeatedly refocus |

`Escape` has one contextual meaning: close the topmost dialog/drawer; while no modal is open, invoke `Stop query` or `Stop query plan` only for the currently running command; otherwise leave editor/content unchanged. The keyboard contract is `Cmd/Ctrl+Enter` for `Run query`, `Cmd/Ctrl+Shift+Enter` for `Build query plan`, and `Escape` for the matching stop action while running. Visible focus is a 2px `--focus-ring` outline with 4px offset; clipped containers use an inset 2px `--focus-ring` ring with no loss of focus area.

## Theme Contract

- Light and dark modes have identical hierarchy, information, controls, target sizes, focus geometry, empty/error/limited states, graph/list parity, and export/offline behavior.
- The theme initializes before first paint from bounded UI preference, otherwise system preference. Storage failure falls back to the current system theme without blocking use.
- Theme switching never reloads a database, resets panels, reruns SQL/layout, dismisses errors, or changes service-worker state.
- Forced-colors mode preserves native control appearance, borders/focus, canvas/list selection, and status meaning; decorative background grid may disappear.
- Dark theme does not use pure black and light theme does not use pure white as the dominant field; use the canonical paper tokens.

## Performance and Scalability UI Contract

- Operations longer than 150ms expose a stable busy state without blocking unrelated navigation; only an active serialized database command disables `Run query`/`Build query plan`/database replacement per the owning contract.
- Never render more than one 50-row result page in the DOM. Wide tables scroll within their labelled region. Large text/BLOB values use bounded previews before main-thread transfer.
- Catalog/graph limits must produce searchable limited/subgraph states with exact counts, not indefinite skeletons. The 75-node full-layout threshold remains provisional until Phase 6 evidence ratchets it.
- Lazy editor, graph, layout, and export/offline chunks display a compact text loading state. Failure uses the exact owning labels `Retry editor`, `Retry diagram`, `Retry diagram layout`, `Retry export`, or `Retry offline setup`; no generic retry label and no automatic loop.
- Stop acknowledgement and rehydration are separate UI timings. Show `Stopping query…` or `Stopping query plan…` only until worker termination acknowledgement; then `Reopening database…` with retained draft. Never present rehydration time as stop latency.
- Bundle/performance regression does not justify hiding accessibility text, reducing target sizes, dropping the relationship list, or raising a safety cap. Use subset/limited behavior.

Audit findings (summary)

Critical 1
Incomplete token map. The plan lists 3 swatch hex codes per palette; each palette ships 7–10 tokens (background, body fg, muted fg, heading, border, accent, link, blockquote bg, code bg, code fg). Define the full tokens table before any CSS author starts work.
Critical 2
Cloud fails WCAG AA. #666663 on #bfbfba is ~3.0:1 contrast — below the 4.5:1 minimum for body text. As specified the palette is unreadable; needs an added body-fg outside the 3 swatches OR repositioning as accent-only.
Critical 3
Surface scope undefined for mindmap / connection graph / insights / chat. Plan only mentions .preview-pane. These features use --fg-default etc. Decide: (a) palette applies to all reader-like surfaces, (b) only .preview-pane, or (c) preview + on-this-page only, with mindmap/graph staying neutral. The user explicitly flagged these as features not to jeopardize.
Critical 4
CSP hash regeneration on the pre-paint script. Touching an existing inline script changes its sha256. Externalize palette pre-paint into reader-palettes.js loaded synchronously in <head> before the inline body script. Keeps CSP untouched.
High
Mermaid re-render strategy unspecified (perf bottleneck on doc with 20+ diagrams). highlight.js theme swap unspecified (use disabled-link flip, both stylesheets already precached). Cross-tab storage sync absent. Print stylesheet implementation absent. No transition smoothing on palette switch (will flash).
Medium
Mobile swatch grid sizing (6 × 44px touch target = 264px row). Edit-to-preview visual whiplash for dark palettes. Reading panel growth on mobile. Tests don't cover mindmap/graph/ insights interaction, mermaid re-render perf, contrast verification per palette, cross-tab sync.
Naming
"Book Cloth" is unusual outside of design audiences. Consider tooltips on each swatch. "Manilla" (proper spelling: "Manila") — minor.

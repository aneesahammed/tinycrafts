Cmd / Ctrl + K trigger — three options

Same toolbar, same surrounding actions. Only the palette trigger changes. Light and dark themes shown side by side because both ship.

Recommended

Option A — Inline search bar

Input-shaped trigger with magnifier, placeholder, and visible ⌘K hint. Linear / Vercel / Slack pattern.

Why it works
Input-shaped element reads as a different visual category than the surrounding buttons, so it adds less perceived clutter than the current Search button — despite being wider. The visible ⌘K kbd badge actively teaches the shortcut.
Track record
Linear, Vercel, Slack, Notion, GitHub. The dominant pattern for command-palette triggers in 2024–2026.
Trade-off
Wider than a button. Within a week most users graduate to keyboard-only and stop seeing it, so the cost is short-lived.

Why it works
Smallest possible footprint. Visual quiet matches markv's minimalist aesthetic. The icon is the affordance; the keyboard hint lives in the tooltip on hover.
Track record
Many CMS apps, Obsidian, older Notion. Workable but discoverability suffers.
Trade-off
Many users will read the magnifier as content-search inside the current document and never discover the palette. Without the visible kbd, the shortcut takes longer to teach.
Purist

Option C — Pure shortcut, no visible trigger

Remove the trigger. ⌘K lives only in a "?" help overlay and a faint hint near the brand. Raycast / VS Code style.

Why it works
Quietest toolbar of all three. The faint ⌘K-to-search badge near the brand is the only hint, and it harmonizes with the writing-tool aesthetic. Power-user purist.
Track record
Raycast, VS Code, Sublime Text, vim. Works when the audience already expects keyboard-driven UI.
Trade-off
The palette is effectively invisible to casual users. The brand hint is small enough to miss. A "?" overlay needs to be wired up to compensate.
